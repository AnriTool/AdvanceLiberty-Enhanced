# Текстовые языковые пакеты

[English](../en/LOCALIZATION.md) | **Русский**

Основой исполнения остаётся проверенный USA ROM. Изображения, заставки и
текстуры в рамках этой работы не переводятся. Инструмент готовит внешние
UTF-8-пакеты, runtime находит их в `languages/` и загружает выбранный в
Enhanced Options пакет. Строки и
шрифты меняются только в памяти; файл ROM и нативные DLL не изменяются.

## Запуск в игре

При первом обычном запуске игра сама создаёт `languages/en.json` — пакет v2
**English (editable)** со всеми 1774 распознанными английскими записями.
Его можно редактировать напрямую либо скопировать под другим именем и изменить
`language`, `name`, тексты и шрифт. Чтобы увидеть правки, выберите этот пакет
в настройках и сохраните изменения. Автоматически язык не переключается.

Существующие значения в `en.json` сохраняются. При расширении каталога игра
добавляет только отсутствующие ID; повреждённый JSON остаётся нетронутым.
Удаление или перенос файла позволяет
получить свежий оригинал при следующем запуске. Повторы и консольные проверки
его не создают. Ошибка записи выводится в консоль и не мешает запуску игры.
Сгенерированные игровые тексты остаются локальными и не попадают в Git.

Включены 1156 сюжетных пятиъязычных таблиц и отдельный банк из 618 записей:
rampage, медицинские, пожарные, полицейские и таксомоторные задания, меню,
статистика и названия. Текст на изображениях в экспорт не входит.

Из рабочего каталога игры:

```powershell
.\Play.bat
```

Порядок выбора:

1. Поместите JSON-пакет непосредственно в `languages/` (подкаталоги не сканируются).
2. Запустите игру, откройте **Esc → Language**.
3. Выберите пакет и нажмите Enter. Esc возвращает в главное меню настроек.
4. Выберите **Save and return** — язык применяется к текущей игре.

Смена языка сохраняет CPU, устройства, таймеры, прогресс и звук в памяти.
Игра не перезагружается, промежуточные сейвстейты не создаются. Уже
скомпонованное сообщение может остаться до штатной перерисовки или следующей
реплики; новые строки и рисунки букв берутся из выбранного пакета.
Старые области текста сохраняются в памяти для незавершённых обращений,
а повторное переключение на тот же пакет переиспользует его область.
**Original game / ROM**
отключает внешний пакет и сохраняет штатный выбор языка самой игры.
Изменения можно отменить через **Discard and return** или Esc в главном
меню настроек. Выбор хранится в `data/config/enhanced.cfg`, например
`Language = ru-demo.json`; старый файл без этой строки означает Original.

При запуске и при открытии настроек список пакетов обновляется, каждый пакет
проверяется целиком. Можно добавить новый JSON без перезапуска. Повторный
выбор уже активного языка и сохранение настроек перечитывает его файл — это
позволяет проверять правки перевода во время игры. Неподдержанные,
повреждённые и несовместимые пакеты пропускаются с пояснением в консоли.
Если сохранённый пакет удалён или перестал проходить проверку, игра
запускается со штатным языком ROM. Имена сохраняются без абсолютных путей,
поэтому каталог игры можно переносить. Поиск не зависит от текущего каталога:
в проекте используется `languages/` от корня рабочего каталога, в переносимой сборке —
`languages/` рядом с exe.

Для собственного перевода скопируйте `languages/en.json` под новым именем,
измените `language`, `name`, добавьте алфавит и шрифт, затем переведите `entries`.
Новые ID банка имеют вид `ui.015b`; существующие `text.00cabfac` сохраняются.

Для диагностики сохранённый выбор можно разово переопределить параметром
`-LanguagePack PATH`; этот параметр не меняет сохранённые настройки.
У исполняемого файла соответствующий аргумент — `--language-pack PATH`. Пакет требует точного
USA ROM по SHA-256 и библиотек AOT с одной инструкцией на блок. Режим
интерпретатора и дифференциальная проверка блоков с пакетом отклоняются.

Пакет действует независимо от языка, выбранного в исходном меню игры:
пять указателей каждой таблицы направляются на перевод или английский
запасной вариант. Данные перевода размещаются после исходных 16 MiB в
виртуальной области картриджа. Исходная адресация EEPROM сохраняется отдельно
от размера этой области: дополнительные тексты не меняют видимость сохранений.

Исходные латинские буквы, акценты, значки кнопок и пунктуация сохраняются.
Другие символы, их пиксельные рисунки и соответствия регистра задаются самим
JSON-пакетом, без изменения Rust или пересборки. Один пакет может смешивать
несколько алфавитов. Шрифт добавляется в UI-наборы и варианты диалогового окна.
Кат-сцены используют отдельный набор пикселей и пропорциональные ширины:
их копии тоже формируются из `font`, с сохранением исходных латинских знаков.
Исходный парсер символов
выполняется нативно; его возврат расширяется для приватных кодов новых букв.
Байты исходного апострофа, испанского ¡ и других штатных символов не заняты.

Текущие ограничения обычного шрифта: до **110 собственных знаков**, каждый в ячейке
**8×8** пикселей с учётом необязательной тени. Исходная игра определяет шаг
букв и направление письма; сложная типографика, лигатуры и письмо справа
налево пока не реализованы. Это формат пиксельного шрифта, а не загрузчик TTF.
Русский пример использует 33 рисунка 5×7 и явные соответствия строчных букв
прописным. Для другого языка таких автоматических соответствий нет:
нужные варианты добавляются в `alphabet` либо `font.aliases`.

Текущий экспериментальный предел — 609 символов на строку. Длина перевода
может отличаться от длины оригинала, и перенос по словам выполняет игра.
Этот предел не гарантирует правильную раскладку во всех окнах: особо длинные
реплики, страницы и временные ограничения ещё требуют проверки по категориям.
Символы без рисунка и без штатного представления отклоняются с пояснением.

При записи сессии точные байты пакета копируются в `language-pack.json` внутри
каталога записи, включая алфавит и шрифт. `scripts/windows/replay.ps1` и runtime автоматически читают этот снимок рядом
с `input.gba-input`, поэтому исходный пакет можно редактировать, не меняя старый
повтор. Если метаданные требуют пакет, а снимок отсутствует, повтор сообщает
ошибку. Выбор языка из настроек не применяется к повторам: приоритет имеет
пакет самой записи (либо явно переданный параметр диагностики).
Переключения во время игры записываются с кадром и полным снимком JSON в
строки `# language` существующего `input.gba-input`; дополнительные файлы
состояния не создаются. Повтор применяет те же переключения независимо от
нынешнего содержимого каталога `languages/`.
Для диагностики `--text-trace NEW.csv` записывает обращения к таблицам
с кадрами, ID и языковыми слотами; рядом создаётся `NEW.glyphs.csv` для шрифта.

## Источники текста в ROM

В USA ROM подтверждены 1156 таблиц, каждая из пяти пар `(language, pointer)`:
0 = English, 1 = Español, 2 = Français, 3 = Italiano, 4 = Deutsch.
Итого 5780 языковых записей. Среди них миссионные реплики и сообщения
`MISSION SUCCESS` / `MISSION FAILED`. Эти строки хранятся без сжатия,
с нулевым завершением, в однобайтной Latin-1.

Отдельно подтверждён UI-банк: пять массивов по 618 указателей, с размером
массива `0x9A8`. Игра читает его через функцию `0805e330`. Его ID `ui.0000`…
`ui.0269` относятся к одному индексу во всех пяти языках. В отличие от общего поиска строк, инструмент
не считает каждую последовательность похожих указателей языковой таблицей
и не отправляет внутренние имена миссий и объектов в перевод.

В предоставленном европейском ROM найдены те же 1156 таблиц, смещённые на
`0x3B0`. При импорте проверены и совпали байты всех пяти языков каждой
таблицы. Для этих текстов европейский ROM не добавляет переводов сверх USA.

В предоставленном `ru.gba` структура таблиц тоже сохранилась. В английском
слоте непусты 1152 записи, в испанском/французском/итальянском — 0,
в немецком — 6. Изменены пиксельные данные текстовых шрифтов.
Строки вроде `CAÊAÛ` демонстрируют смешение ASCII с собственными кодами букв.
Обычное чтение как Latin-1 или Windows-1251 не восстанавливает русский текст.
Это объясняет, почему результат Advance Studio выглядит неправильным;
само наличие такого текста не доказывает повреждение ROM.

Для него предусмотрен импорт с явно заданной таблицей символов, но готовая
проверенная таблица русского шрифта ещё не составлена. Автоматический импорт
этого ROM без неё отклоняется, чтобы не выпускать пакет с испорченным текстом.

## Инструмент

`tools/localization/texts.py`, Python 3.10+, без внешних зависимостей.
Команды ниже выполняются из рабочего каталога игры.

```powershell
# Определить известную версию, количество таблиц и заполненные языки
python tools/localization/texts.py inspect roms/usa.gba
python tools/localization/texts.py inspect roms/ru.gba

# Извлечь каталог со всеми пятью исходными языками
python tools/localization/texts.py extract roms/usa.gba artifacts/text/usa.json

# Создать пустой русский шаблон с алфавитом и шрифтом из примера
python tools/localization/texts.py new-pack artifacts/text/usa.json artifacts/text/ru.json --language ru --name "Русский" --font-from resources/legacy-language-v1-font.json

# Проверить отредактированный пакет
python tools/localization/texts.py validate artifacts/text/usa.json artifacts/text/ru.json

# Создать пакет на основе одного из встроенных языков
python tools/localization/texts.py new-pack artifacts/text/usa.json artifacts/text/fr.json --language fr --name "Français" --copy-language fr

# Прочитать французский из известного европейского ROM и сопоставить с USA
python tools/localization/texts.py import-rom roms/usa.gba roms/europe.gba artifacts/text/fr-europe.json --language fr --name "Français" --slot fr

# Перевести старый пакет v1 в новый самостоятельный пакет v2
python tools/localization/texts.py upgrade-pack artifacts/text/old-ru.json artifacts/text/ru-v2.json
```

Существующий выходной файл не перезаписывается. Для повторного экспорта
выберите новый путь. Неизвестный ROM разрешён для диагностики `inspect`,
но не для автоматического сопоставления с USA.

## Формат пакета

Идентификатор `text.00cabf84` обозначает запись в таблице USA, а не адрес
конкретной языковой строки. Две одинаковые реплики в разных таблицах сохраняют
разные ID. Идентификаторы привязаны к точному SHA-256 исходного USA ROM;
поддержка нового базового ROM потребует явного сопоставления.

Минимальный частичный пакет со штатным латинским шрифтом:

```json
{
  "version": 2,
  "language": "en-custom",
  "name": "Custom text",
  "entries": {
    "text.00cabfac": "TRY AGAIN"
  }
}
```

Для собственного алфавита добавляются `alphabet` и `font`. Пример одного
греческого знака, который можно использовать сразу и в тексте, и в имени пакета:

```json
{
  "version": 2,
  "language": "el-example",
  "name": "Omega Ω",
  "alphabet": "Ω",
  "font": {
    "width": 5,
    "height": 7,
    "shadow": false,
    "glyphs": {
      "Ω": [".###.", "#...#", "#...#", "#...#", ".#.#.", ".#.#.", "##.##"]
    },
    "aliases": {"ω": "Ω"}
  },
  "entries": {"text.00cabfac": "Ω ω"}
}
```

`alphabet` задаёт уникальные Unicode-символы; `glyphs` должен содержать ровно
их рисунки. В каждой строке `#` означает пиксель, `.` — прозрачность. Число
строк равно `height`, длина каждой — `width`. При `shadow: true` добавляется
тень на один пиксель вправо и вниз, поэтому ширина и высота должны быть не
больше 7. Без тени допустимы размеры от 1 до 8. `aliases` необязателен:
каждое соответствие направляет один символ непосредственно на знак из
`alphabet`, без цепочек и дополнительной ячейки. Пробел, управляющие символы,
`@` и `%` зарезервированы. Латинские буквы тоже можно переопределить рисунками.

Готовый русский алфавит и шрифт: `resources/legacy-language-v1-font.json`.
Пример другого алфавита: `tools/localization/examples/greek-symbols.json`. Название языка в настройках
использует тот же шрифт; для меню крупные рисунки вписываются в ячейку 5×7.

### Цветной шрифт меню и статистики

Необязательный `color_font` описывает отдельные рисунки для штатного цветного
шрифта 16×16. Он использует тот же `alphabet` и соответствия `font.aliases`,
но рисунки и расстояния между буквами независимы от обычного `font`.
Готовый полный набор находится в `languages/ru.json`.

- `width`, `height`: размер рисунка от 1 до 16, внутри ячейки 16×16.
- `glyphs`: ровно по одному рисунку для каждого знака из `alphabet`. Строки
  содержат шестнадцатеричные индексы `0`…`f`; `.` равнозначна прозрачному `0`.
- `palette`: 16 индексов штатных оттенков игры от 0 до 15. Первый всегда 0.
  Например, замена элементов 1, 2, 3 на 15 делает заливку белой при сохранении
  обводки и тени. Игра продолжает выбирать палитру и подсветку своего меню.
- `advance`: шаг буквы в пикселях, чётное число от 2 до 18. По умолчанию
  ширина рисунка плюс два пикселя, округлённая вверх до чётного числа.
- `advances`: необязательный объект с отдельным шагом для конкретных букв;
  ключи относятся к `alphabet`, значения имеют те же ограничения.

В русском наборе рисунки имеют размер 10×16 и шаг 10. Исходные латинские
буквы, цифры и их метрики сохранены. Если `color_font` отсутствует, игра
строит цветные буквы из обычного шрифта пакета; прежние пакеты продолжают
работать. `new-pack --font-from` и `upgrade-pack --font-from` копируют также
`color_font`, если он есть в исходном файле.

Шрифт применяется в нативном выводе меню и статистики, а также при смене
языка в текущей игре. После правки JSON выберите активный язык повторно и
нажмите Save and return. Уже нарисованные игровые строки обновляются при
следующей штатной перерисовке.

`version` — целое число версии структуры, сейчас **2**. Строковое поле
`format` больше не используется. Старое `scope` описывало подтверждённые
пятиъязычные таблицы, а `base_rom_sha256` фиксировало USA ROM. В новом пакете
их нет: движок сам проверяет точный USA ROM и допустимые ID. Технический
каталог извлечения по-прежнему содержит сведения о ROM. Необязательные
`source_rom_sha256` и `source_slot` сохраняют происхождение импортированного
перевода и не нужны при ручном переводе.

Старые пакеты v1 и снимки записей продолжают загружаться. Для них сохранён
неизменяемый шрифт в `resources/legacy-language-v1-font.json`; новые пакеты
не зависят от него. `upgrade-pack` копирует его внутрь выходного v2-пакета.

Пустая или отсутствующая строка означает английский запасной вариант.
Необязательный `fallback` допускает только `en`; по умолчанию он уже выбран.
Файл сохраняется в UTF-8; длина перевода не ограничена исходным местом в ROM.
Проверка отклоняет чужой базовый ROM, неизвестные ID, повторяющиеся JSON-ключи,
неизвестную версию, неверные рисунки/соответствия и неподдержанные управляющие
символы. Длинные строки дают предупреждение. Символы сохраняются без замены
на `?`; валидатор отдельно сообщает `requires_extended_font: true` и число
`custom_glyphs`. Поле `runtime_supported` отражает ограничения текущего runtime;
`runtime_errors` перечисляет слишком длинные строки и неподдержанные символы.
Структурно корректный пакет с такими ошибками пригоден для дальнейшего
редактирования, но игра откажется его загружать. Проверка также требует
сохранить динамические подстановки `%...` и значки кнопок `@1`…`@4`
из исходной английской строки (порядок можно менять). Цветовое выделение
`@0`, `@8`, `@9` может отличаться — так устроены и исходные переводы.
Окончательная раскладка требует проверки в игре.

Для нестандартного ROM `--charmap FILE.json` принимает объект вида
`{"CA": "М"}`: двухзначный код байта → один Unicode-символ. Все встреченные
байты выше ASCII должны иметь соответствие; ASCII сохраняется, если не задано
иначе. Неполная карта отвергается. Это механизм для будущего проверенного
декодера, не готовый русский импортёр.

## Перевод собственного меню

В пакет v2 можно добавить необязательный объект `menu` рядом с `entries`:

```json
"menu": {
  "quit_to_menu": "В главное меню",
  "quit_to_desktop": "На рабочий стол",
  "quit_to_desktop_action": "На рабочий стол...",
  "save_failed": "Ошибка сохранения: {error}"
}
```

Это фрагмент существующего пакета, а не самостоятельный файл. Полный каталог
стабильных ключей с английскими исходниками — `resources/menu-en.json`;
частичный русский пример — `resources/menu-ru-example.json`. Переводятся
пауза, списки Options, настройки ПК, привязки управления, подсказки и диалог
выхода. Штатные страницы Brief/Stats/Credits и стартовые страницы продолжают
использовать игровые переводы из `entries`.

Пустые и отсутствующие значения используют исходную подпись. Для штатных
пунктов паузы сохраняется перевод из `entries`, если нет явного переопределения
в `menu`; переименованный `quit_to_menu` по умолчанию использует Quit to Menu.
Старые пакеты без `menu` загружаются по-прежнему. `languages/en.json` при запуске
дополняется отсутствующими ключами меню без перезаписи авторских значений.
Команда создания нового пакета также включает раздел `menu`.

Подписи используют игровой шрифт; кириллица и другие дополнительные символы
берутся из `alphabet`, `font.glyphs`, `font.aliases` и `color_font` выбранного пакета.
Раздел `menu` сам по себе шрифт не добавляет. Для русского примера используйте
пакет с русским шрифтом. Пишите короткие однострочные подписи: длинные строки
обрезаются по ширине доступного места. Лимит — 512 символов, управляющие
символы запрещены. Неизвестные ключи и отсутствующие глифы отклоняются.
В шаблонах сохраняйте подстановки `{error}` и `{file}` из английского
исходника; положение подстановки можно менять. Синтаксис игровых строк
`%...` и `@1` для этого раздела не применяется.

Проверка `validate-pack` проверяет оба раздела и сообщает `menu_translated`.
Чтобы применить изменения без перезапуска, снова выберите пакет в
Enhanced Options → Language и нажмите Save and return.
