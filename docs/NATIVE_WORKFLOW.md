# Обновление нативного покрытия после игры

После завершения игры запустите из каталога проекта:

```powershell
.\UpdateNative.cmd
```

Команда собирает новые инструкции из завершённых записей `data/sessions/`,
обновляет `native/usa/coverage/sessions.csv`, пересобирает профиль `sessions`
через MinGW x64 GCC и устанавливает DLL/C с обновлением манифеста. Rust,
Cargo и MinGW нужны те же, что для обычной сборки проекта; Python не нужен.
Остальные три профиля не пересобираются. Если новых вариантов нет и число
вариантов соответствует установленному профилю, компиляция пропускается.

Обычный режим не выполняет длинные повторы записей. Он проверяет SHA-256
USA ROM, формат и выравнивание инструкций, совпадение байтов ROM из аудита,
успешную генерацию без пропуска неподдержанных инструкций и хеши установленных
файлов. Несовместимая запись исключается целиком с объяснением в отчёте;
незавершённые записи и `fallbacks.partial.csv` не используются. Одинаковые
инструкции не дублируются, разные RAM-варианты одного адреса сохраняются.
Успешная компиляция сама по себе не доказывает эквивалентность исполнения.

Для проверки поведения новых вариантов:

```powershell
.\UpdateNative.cmd -Verify
```

До установки DLL повторяются только записи, которые дали новые варианты.
Требуются ноль интерпретаций и совпадение всех исходных кадров и аудиохешей.
Повторы используют копии `initial.sav`; игровые сохранения не изменяются.
При ошибке генерации или проверки активные DLL остаются прежними.
Полную историческую регрессию имеет смысл запускать после изменений самого
генератора, CPU, прерываний или таймингов, а не при каждом пополнении CSV.

Можно выбрать одну запись:

```powershell
.\UpdateNative.cmd -Session session-0123456789abcdef0123456789abcdef -Verify
```

Для нескольких записей используйте PowerShell-скрипт напрямую с массивом
`-Session @('session-a', 'session-b')`. При явном выборе несовместимая запись
завершает сбор покрытия ошибкой, вместо автоматического исключения.
Очень старые записи могут перестать совпадать после изменений шрифтов или
самого приложения: несовпадение нужно исследовать, оно не обязательно
означает ошибку добавленного нативного кода.

## Раздельные команды

```powershell
.\CollectNative.cmd              # Только накопить CSV, без компиляции
.\CollectNative.cmd -DryRun      # Посмотреть результат без изменения CSV
.\RebuildNative.cmd              # Пересобрать и установить sessions из CSV
```

`CollectNative.cmd` не меняет действующую DLL и её манифест: до пересборки
CSV может содержать больше вариантов, чем установленная библиотека.
`UpdateNative.cmd` распознаёт такое незавершённое обновление по числу строк.
`-Force` принудительно пересобирает профиль; `-SkipBuild` использует готовые
Rust-инструменты. `-Gcc PATH` позволяет задать MinGW GCC.
Если покрытие было собрано отдельно, `-Verify` проверит одну совместимую
запись; для точного выбора используйте `-Session` или `-VerifySession` ниже.

Расширенные параметры сборки доступны через существующий скрипт:

```powershell
.\tools\rebuild-native.ps1 -NativeProfile sessions -Install -VerifySession session-0123456789abcdef0123456789abcdef
.\tools\rebuild-native.ps1 -NativeProfile all -Install
```

Закройте игру перед установкой DLL. Предыдущие DLL/C и манифест сохраняются
в `artifacts/native-build-.../before-install/`; при ошибке установки скрипт
восстанавливает изменённые файлы. Сборщик сохраняет предыдущий CSV и JSON
отчёт в `artifacts/native-collect-.../`. При неудачной компиляции собранный
CSV остаётся на месте для исправления или повторной сборки; для возврата
покрытия можно скопировать `before-sessions.csv` из отчёта обратно в
`native/usa/coverage/sessions.csv`.

В Git включаются изменённый CSV и `native/usa/manifest.json`; DLL и C
остаются локальными результатами сборки.

Тесты сборщика и установки, включая отбрасывание несовместимого аудита,
сохранение разных RAM-вариантов и откат при частичной неудаче установки,
входят в `test.ps1`. Отдельный запуск:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/tests/native-coverage.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/tests/native-install.ps1
```

## Зачем нужны проверки

В последних сериях простого пополнения покрытия подтверждённых регрессий
не было. В ранней реализации проверки выявили [нарушение границ исполнения
многокомандных блоков](history/aot/PRECISION-20261023.md): 5 дополнительных
инструкций и 12 тактов после границы кадра. Это исправлялось устройством
исполнения, а не пополнением списка инструкций. Позднее генератор отклонил
[старый аудит с несовпадающими байтами ROM](NATIVE-20261024.md).
