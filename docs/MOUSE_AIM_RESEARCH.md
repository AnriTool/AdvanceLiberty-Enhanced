# Независимые WASD и прицеливание мышью: техническое исследование

Дата: 24 октября 2026. Профиль: GTA Advance USA BGTE.

После этого исследования добавлена первая экспериментальная реализация.
Её актуальное включение, устройство и проверки описаны в [MOUSE_AIM.md](MOUSE_AIM.md).
Ниже сохранены результаты исходного исследования.

## Вывод и граница выполненной работы

Режим технически реализуем. В изолированной копии runtime подтверждены
поворот изображения персонажа и изменение направления настоящих выстрелов
без замены записанного ввода WASD. Рабочий режим с живым курсором пока
не добавлен в игру: выполнены исследование, трассировка и доказательство
возможности на фиксированных углах. Обычные запускатели, src/, ROM, DLL,
сохранения и конфиги не изменялись этим исследованием.

Перед работой изучены README.md, PROJECT.md, CONTROLS.md, WIDESCREEN.md,
HUD_LAYOUT.md и относящиеся к привязке персонажа/камеры исторические документы.
Уже существовавшие изменения building_material.rs, object_projection.rs,
README.md и WIDESCREEN.md сохранены.

## Что устроено сейчас

Controls/InputLatch преобразуют WASD в направления GBA, J/MouseLeft — в A.
Desktop читает кнопки мыши, но не передаёт координаты в игровую логику.
Исходная игра сама связывает ходьбу, угол физического объекта, позу и оружие.
Поэтому добавить курсор только в таблицу привязок недостаточно.

Проверка control_context.rs уже даёт безопасный способ найти текущего
управляемого персонажа: указатель 02000f10, тип объекта 2, физика actor+24,
анимация actor+28. Адреса конкретных аллокаций нельзя фиксировать в реализации.
В исследованной сессии actor=0202de90, physics=02002350, animation=02002510.

## Найденные поля и инструкции USA ROM

Адреса ниже — адреса гостевых инструкций, без Thumb-бита. При проверке
ключей диспетчера runtime к Thumb-адресу добавляется бит 0.

| Поле / инструкция | Назначение и наблюдение |
| --- | --- |
| physics+0 / +4 / +8 | Координаты X/Y/Z; сравнивались побайтно по кадрам |
| physics+0x0c | Угол; фиксированное представление, старшие 16 бит — единицы угла |
| physics+0x10 | Копия угла в физическом обновлении |
| physics+0x18 / +0x20 / +0x24 | Скорость и компоненты перемещения |
| 08039b00 | Общая точка записи направления по обработанным клавишам; среди значений 0x01000000 вправо, 0x03000000 влево |
| 0801d21a..0801d266 | Копирует угол, читает тригонометрическую таблицу 08ca2d28 и вычисляет компоненты скорости |
| 08018bb8 | Читает угол персонажа для выбора/подготовки изображения анимации |
| 0801453e | Читает привязанный угол при размещении графической части |
| 08024a24 → 08024a26 | Читает угол стрелявшего, записывает projectile+0x68 |
| 08024c26 → 08024c28 | Повторно переносит угол стрелявшего в projectile+0x68 |
| 08024f90 | Использует параметры выстрела, включая его угол, для размещения эффекта/выстрела |
| 080270bc | Дополнительное чтение угла на исследованном маршруте; включено в пробную подмену, полная семантика отдельно не восстановлена |

Это не только косметический поворот спрайта: собственное поле направления
созданного выстрела действительно получает другой угол. На контрольном
изображении кадра 1000 видны выстрелы слева в оригинале и справа в варианте
с углом 256. Вариант с углом 0 поворачивает персонажа по другой оси.

Физика читает угол и для движения. Постоянно перезаписывать physics+0x0c
перед каждым кадром нельзя: это затронет WASD и другие потребители угла.
Для эксперимента избирательно подменены результаты чтений в пяти найденных
точках, только когда адрес относится к физике текущего игрока. Чтения
физики движения продолжают получать исходный угол. Тест использует
существующие AOT DLL через RtApi, не патчит ROM или сгенерированный C.

## Эксперименты на последней сессии

Источник: session-1e52cb6f98c34c3c8864653da1d67b2b, 4291 кадр.
Файлы исследования: artifacts/aim-research-20261024/.
Все запуски используют копию initial.sav, а не текущий игровой прогресс.

1. Снята трасса записи полей игрока и чтения угла с PC/LR.
   Исходные 1800 кадров диагностической сборки совпали с записью по всем
   видео- и аудиохешам. Отдельный контроль 1500 кадров также совпал.
2. На той же последовательности кнопок выполнены варианты с фиксированными
   углами 0 и 256. Подмена включается с кадра 730. Анализ координат охватывает
   кадры 730..1499 — 770 снимков на каждый вариант.
3. В варианте 256 все 770 X/Y/Z совпали с контролем, хотя направление
   изображения и части выстрелов отличается. Все 18 зарегистрированных
   выстрелов получили 0x01000000. В контроле выстрелы имели четыре разных угла.
   Это прямое подтверждение возможности двигаться независимо от взгляда.
4. В варианте 0 все 18 выстрелов получили нулевой угол; X/Y/Z отличаются
   от контроля на 139 снимках, начиная с 1264. Причина этого расхождения
   отдельно не установлена. Изменение направления выстрелов и ветвей кода
   меняет состояние мира/время гостевого исполнения; полную независимость
   всех углов по этому варианту утверждать нельзя.

Оба экспериментальных запуска по 1500 кадров имели по 2 интерпретированных
инструкции. Они не доказывают отсутствие откатов на полном маршруте.
Сравнение изображений: artifacts/aim-research-20261024/comparison.png.
Машиночитаемый результат: verification.json; пересчёт — verify.py.

Отдельно выполнен полный контрольный повтор рабочей сборкой с Enhanced
и --widescreen: все 4291 видео-/аудиохеша совпали с записью. Принято 780
сцен, rejected=0. Интерпретированных инструкций — 11678, столько же,
сколько в исходной сессии; это не новый нулевой маршрут AOT. Полный повтор
проверяет сохранность исходного поведения, а не готовность нового режима.
SHA-256 текущего usa.sav, controls.cfg и enhanced.cfg до/после совпадают.

### Повтор исследовательского опыта

Копия исходников и диагностический модуль находятся в runtime/src/ внутри
каталога артефактов. prepare.py восстанавливает её main.rs из рабочего
src/main.rs и подключает только исследовательскую трассировку. Сборка:

```powershell
cargo build --release --offline `
  --manifest-path artifacts/aim-research-20261024/runtime/Cargo.toml `
  --target-dir artifacts/aim-research-20261024/target
```

Использовать обычные аргументы headless multi, четыре DLL из manifest.json,
input.gba-input последней сессии и новую копию её initial.sav. AIM_TRACE
указывает новый CSV. Без AIM_ANGLE это контроль; AIM_ANGLE=0 или 256 включает
фиксированный исследовательский угол. Достаточно 1500 кадров. Существующие
файлы трассировки не перезаписываются. Экспериментальный бинарник не следует
использовать как игровой запускатель; живая мышь к нему не подключена.

## Предлагаемая реализация режима

Добавить отдельную настройку экспериментального прицеливания, по умолчанию
выключенную. Существующий Enhanced и Classic должны оставаться доступными.

Поток ввода: получить координаты курсора в фактически показанном viewport,
определить направление от показанного персонажа к курсору и передать угол
в модуль управления гостевой логикой. WASD остаётся в мировых экранных осях;
J/ЛКМ сохраняют существующее действие Fire. Вектор движения не нужно
поворачивать на угол взгляда.

Варианты интеграции: ограниченные обработчики найденных инструкций либо
раздельное хранение угла движения и прицеливания с подстановкой в нужных
фазах обновления. Эксперимент доказывает первый подход, но его список
потребителей ещё не полон. В рабочем коде нужен быстрый путь без подмены,
проверка USA ROM/контекста/принадлежности объекта и единая обработка
основного исполнения и внутренних AOT-выходов. Чтения всех объектов
глобально подменять нельзя. Переменные окружения и подробный CSV из
исследовательской копии не являются проектом рабочего hot path.

### Курсор, Enhanced и 16:9

Нельзя вычислять направление от фиксированного центра окна. Учитываются
letterboxing, fullscreen/HiDPI и текущие логические размеры SDL:
240×160 для оригинального кадра, 720×480 или 854×480 для Enhanced.
Широкий кадр имеет горизонтальный сдвиг 67 пикселей при масштабе 3.

Object projection уже вычисляет точные экранные позиции, привязки к актору
и масштаб. Camera preview показывает историю с задержкой 6 кадров GBA
(около 100 мс). Поэтому использовать текущую физическую позицию вместе
с исторической камерой нельзя: при беге прицел сместится. Надо сохранять
преобразование последнего реально показанного кадра и положение игрока
в нём. Через обратную проекцию на плоскость земли можно получить мировую
цель; угол для выстрела затем вычисляется от текущего положения стрелка.
Точное поведение у самого персонажа следует определить малой мёртвой зоной.

HUD масштабируется отдельно и не задаёт преобразование мирового курсора.
Рендер, его размеры, материалы и раскладку HUD для этого менять не требуется;
нужно предоставить модулю ввода данные показанной проекции. При откате
Enhanced к оригиналу преобразование должно обновляться вместе с кадром.

### Что обязательно проверить до включения пользователю

- Полный набор читателей угла, автоприцеливание/захват цели и направление
  настоящего попадания, а не только трассера. Найденный путь подходит для
  исследованного стрелкового оружия; всё оружие ещё не проверено.
- Произвольные углы, граница оборота и квантизация поз: наличие точного
  угла выстрела не означает наличие бесконечного числа рисунков тела.
- Согласованность туловища, ног и дула при ходьбе боком/назад; существующие
  анимации могут потребовать адаптации. Новые изображения пока не создавались.
- Стрельба во время движения, Sprint/Jump, рукопашный бой, смена оружия,
  посадка/выход, смерть, кат-сцены, пауза, потеря фокуса и выход курсора за кадр.
  Сейчас Sprint намеренно блокирует Fire; это правило следует сохранить.
- Детект OnFoot дополняется игровыми запретами управления: наличие персонажа
  на экране само по себе не разрешает вмешиваться в скриптовое состояние.
- Session сейчас записывает только эффективные GBA-кнопки. Для детерминированного
  повтора нового режима нужен поток углов/целей и включений режима, привязанный
  к кадрам; иначе J и WASD уже не описывают результат игры полностью.
- AOT-покрытие новых направлений/попаданий и отсутствие регрессий Enhanced,
  16:9, HUD, Classic, транспорта и старых записей при выключенном режиме.

Технического блокера в архитектуре не обнаружено. Следующий этап —
ограниченный выключенный по умолчанию режим для пешего стрелкового оружия,
с живым курсором, записью прицела и проверкой указанных переходов.
