# Сборка Linux и структура скриптов

[English](../en/LINUX.md) | **Русский**

Целевая платформа Linux — x86_64 с glibc и рабочим столом X11 или Wayland.
Нативные ELF-библиотеки `.so` создаются из того же версионируемого покрытия
инструкций, что и Windows. Wine и загрузчик Windows DLL не используются.
Для запуска нужен собственный точный неизменённый ROM версии USA.

## Структура исходников

| Путь | Назначение |
| --- | --- |
| `Build.bat`, `Play.bat` | Сборка Windows и запуск из исходников |
| `Test.bat`, `Package.bat`, `Replay.bat` | Проверки, упаковка и повтор записи Windows |
| `CollectNative.bat`, `RebuildNative.bat`, `UpdateNative.bat` | Инструменты покрытия Windows |
| `scripts/windows/` | Реализации PowerShell, вспомогательные скрипты и их тесты |
| `build.sh`, `play.sh`, `test.sh`, `package.sh`, `replay.sh` | Точки входа Linux |
| `collect-native.sh`, `rebuild-native.sh` | Инструменты покрытия Linux |
| `scripts/linux/` | Реализация Linux: стандартная библиотека Python и Bash |
| `scripts/tests/` | Проверки сбора, разделения платформ, отката и упаковки |
| `native/usa/coverage/` | Общее версионируемое покрытие обеих платформ |
| `native/usa/*.dll`, `native/usa/manifest.json` | Библиотеки и манифест Windows |
| `native/linux-x86_64/` | Локальные `.so`, хеши и отпечатки покрытия Linux |

Корневые BAT/SH — удобные команды для разработки. Пользователь готового пакета
запускает нативное приложение напрямую. PowerShell не требует Python. Для
разработки в Linux нужны Python 3.9+, Bash, Rust/Cargo, системный C-компилятор,
CMake и pkg-config. Сгенерированные библиотеки, ROM, пользовательские данные
и сгенерированный C-код не версионируются.

## Сборка и запуск в Linux

В Ubuntu/Debian сначала установите зависимости:

```sh
sudo apt-get install build-essential cmake pkg-config python3 \
  libasound2-dev libpulse-dev libx11-dev libxext-dev libxrandr-dev \
  libxcursor-dev libxi-dev libxss-dev libxinerama-dev libgl1-mesa-dev \
  libudev-dev libdbus-1-dev libwayland-dev libxkbcommon-dev
```

Отдельно установите актуальный стабильный Rust. SDL2 собирается из закреплённой
зависимости и встраивается в программу; драйверы звука, экрана и OpenGL остаются
системными. Первой сборке нужен доступ к Cargo registry. `--offline` работает
только при заполненном локальном Cargo-кеше Linux.

Из корня проекта:

```sh
bash build.sh --native --coverage-only # программа, инструменты и .so без ROM
# Положите свой неизменённый USA ROM в roms/usa.gba, затем:
bash play.sh --skip-build             # сохранения/настройки разработки в data/
bash test.sh --offline
bash package.sh --skip-build          # новая папка и .tar.gz в dist/
```

`bash play.sh` автоматически собирает недостающие и устаревшие компоненты.
Параметр `--rom FILE` задаёт другой путь ROM. `--skip-build` отклоняет устаревшее
покрытие, повреждённые библиотеки и отсутствующие сборки. `CC` или
`--cc /path/to/gcc` выбирает системный компилятор нативной сборки; Windows
кросс-компилятор здесь не подходит.

Для запуска через `./build.sh` и другие команды выполните `chmod +x ./*.sh`,
если в checkout нет права исполнения. Вызов через `bash` работает в любом случае.

Новые профили разработки сохраняют Enhanced-графику/звук/управление, широкий
экран, fullscreen, прицеливание мышью и время жизни предметов 30 секунд.
Для диагностики `bash play.sh --frames 120` ограничивает запуск.

## Покрытие и повтор записи

```sh
bash collect-native.sh --dry-run
bash collect-native.sh --session session-ID
bash rebuild-native.sh --skip-build
bash replay.sh session-ID --skip-build
```

Сбор проверяет байты инструкций ROM, сохраняет варианты RAM, убирает дубли и
отклоняет несовместимую сессию целиком. ROM не изменяется. Пересборка создаёт
все библиотеки в промежуточном каталоге и устанавливает после успешной
компиляции всех профилей; ошибка установки возвращает предыдущий каталог.
Прежние профили сохраняются в `artifacts/`.

Windows и Linux используют общие CSV, но разные бинарники. Пересборка Linux не
заменяет Windows DLL и их манифест. После сбора нового покрытия Windows-профили
нужно пересобрать отдельно. Replay работает с копией исходного сохранения,
сверяет хеши изображения/звука и по умолчанию требует ноль интерпретаций.
Для исследования непокрытых маршрутов есть `--allow-interpreter`.

## Поставка и проверки

Упаковщик Linux создаёт `AdvanceLiberty`, четыре `.so`, манифест платформы,
описания и лицензии, пустые каталоги ROM/языков. ROM, сохранения, записи,
скрипты разработки и извлечённые ресурсы не копируются. `.tar.gz` сохраняет
права исполнения. Существующий выходной каталог не перезаписывается.
Пользователю готового пакета не нужны Rust, C-компилятор, Python или скрипты.

Собирать нужно на самой старой версии glibc, которую планируется поддерживать:
бинарник с новой системы может не запуститься на старой. Это не универсальная
Linux-сборка и не musl. Управление, звук и отображение ещё нужно проверять
на реальных рабочих столах Linux, включая X11 и Wayland.

`.github/workflows/build.yml` собирает и проверяет обе платформы, создаёт нативные
профили из версионируемых снимков инструкций без ROM и упаковывает оба релиза.
[Руководство CI и публикации по тегам](RELEASING.md) описывает артефакты и Releases.
Для игрового replay по-прежнему нужен локальный ROM пользователя.
