# CI-сборки и GitHub Releases

[English](../en/RELEASING.md) | **Русский**

`.github/workflows/build.yml` собирает и проверяет Windows x64 на Windows 2022 и
Linux x86_64 на Ubuntu 22.04. Каждый push ветки, pull request и ручной запуск
workflow создаёт скачиваемые артефакты пакетов на 14 дней. Эти запуски не
публикуют GitHub Release.

Push тега `v*` запускает ту же матрицу и публикует Release только после успеха
обеих платформ. Тег должен точно совпадать с `v` + версия в `Cargo.toml`.
Версия с суффиксом, например `0.1.0-preview.2`, публикуется как prerelease и не
заменяет Latest. Стабильная версия помечается Latest.

## Создание релиза

1. Укажите нужную версию в `Cargo.toml`; обновите `Cargo.lock`, если Cargo его меняет.
2. Закоммитьте и отправьте исходники, включая workflow, скрипты и нативное покрытие.
3. Создайте и отправьте соответствующий тег. Для версии `0.1.0-preview.2`:

```sh
git tag v0.1.0-preview.2
git push origin v0.1.0-preview.2
```

Для следующей опубликованной сборки используйте новую версию и тег. Уже
существующий тег перемещать не нужно. Workflow создаст Release самостоятельно:
заранее делать пустой релиз через интерфейс GitHub не требуется. Для проверки
без публикации выберите **Actions → Build and release → Run workflow** на ветке.

## Файлы релиза

- `AdvanceLiberty-Enhanced-VERSION-win64.zip`
- `AdvanceLiberty-Enhanced-VERSION-win64.zip.sha256`
- `AdvanceLiberty-Enhanced-VERSION-linux-x86_64.tar.gz`
- `AdvanceLiberty-Enhanced-VERSION-linux-x86_64.tar.gz.sha256`

В архивах находятся приложение, четыре нативных профиля платформы, манифест,
описания и лицензии. Пользователь распаковывает папку целиком, добавляет свой
легальный неизменённый ROM версии USA и запускает приложение напрямую.

## CI без ROM

Режим `--coverage-only` AOT-генератора декодирует снимки инструкций, уже лежащие
в версионируемых CSV. Ему не нужен файл ROM, восстановленный ROM, игровые ресурсы
или ROM в secrets. Он проверяет противоречия в перекрывающихся снимках ROM и
сохраняет отдельные защищённые варианты RAM. Полученный C совпадает с обычной
генерацией с проверкой по ROM для того же покрытия.

Windows CI вызывает `scripts/windows/rebuild-native.ps1 -CoverageOnly`, Linux —
`bash build.sh --native --coverage-only`. Созданные DLL/SO/C остаются в git-ignore.
Упаковка исключает ROM, BIOS, извлечённые ресурсы, сохранения, записи и скрипты
разработки. Игровой replay по-прежнему требует локальный ROM пользователя;
он выполняется отдельно от модульных и синтетических проверок публичного CI.

## Публикация

Только задача публикации получает `contents: write`; сборка и PR работают с
правами чтения. Достаточно штатного `GITHUB_TOKEN` репозитория: личный токен
и ROM в secrets не нужны. Настройки репозитория/организации должны разрешать
GitHub Actions и запрошенное workflow право записи релизов.

`scripts/ci/release.py` требует оба архива и сверяет их SHA-256. Он загружает
файлы в черновик и публикует после успешного прикрепления. Ошибка загрузки
оставляет черновик, который можно продолжить повторным запуском. Файлы
опубликованного Release не заменяются: повтор для того же коммита оставляет
полный публичный релиз без изменений. Другой коммит или неполный уже
опубликованный релиз приводят к явной ошибке.

[Поведение GitHub CLI](https://cli.github.com/manual/gh_release_create) и
[права workflow](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions).
