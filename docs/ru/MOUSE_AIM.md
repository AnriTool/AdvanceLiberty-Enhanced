# Экспериментальное прицеливание мышью

[English](../en/MOUSE_AIM.md) | **Русский**

Для нового профиля прицеливание включено по умолчанию.
Переключатель: **Esc → Enhanced Options → On-foot bindings → Mouse aim (exp.)**.
Затем Esc → **Save and return**. Существующие профили не перезаписываются.

В Enhanced пешком удерживайте **ПКМ**: курсор превращается в простой
пиксельный прицел, персонаж поворачивается к нему; J и ЛКМ стреляют
в направлении взгляда. Без удержания курсор не влияет на поворот.
WASD/стрелки двигают по прежним экранным осям,
независимо от взгляда. Все переназначения действуют как раньше.
Sprint по-прежнему блокирует Fire, Jump сохраняет своё действие.
При курсоре непосредственно у ног сохраняется последний угол.

Режим действует только в пешем Enhanced-управлении. Classic, транспорт,
пауза/меню настроек и потеря фокуса отключают подмену. Выход мыши из окна
или игровой области с чёрными полосами также её отключает. Активные кнопки
геймпада используют исходную раскладку без мышиного прицела.

Конфиг: `MouseAim = true` перед `[GBA]` в controls.cfg. Отсутствующее поле
означает false; F5 перечитывает значение. Discard and return отменяет
изменения, Save and return сохраняет. F8 → Classic отключает режим, не
стирая сохранённую настройку.

Кнопка удержания настраивается в **On-foot bindings → Aim (hold)**:
Enter заменяет привязку, Insert добавляет альтернативу, Delete отключает.
Список прокручивается при выборе нижних строк. В `[OnFoot]` это поле
`Aim = MouseRight`; старые конфиги получают ПКМ автоматически. Если ПКМ
уже занята другим пешим действием старого конфига, его привязка сохраняется,
а Aim следует назначить вручную. Удержание при выходе из меню или смене
контекста требует отпускания кнопки, как и другие действия Enhanced.

## Отклик поворота

У первой версии угол тела попадал в ту же историю, что и камера: добавлялись
6 кадров GBA (около 100 мс) и ожидание обновления исходной позы.
Теперь при включённом режиме только проверенные части управляемого персонажа
получают актуальный угол перед композицией каждого Enhanced-кадра. Точка
вращения остаётся на показанном положении ног; камера, перемещение, NPC,
пули и HUD сохраняют свою временную шкалу. Для частей сохраняется реально
прочитанный при размещении угол, поэтому поправка не накапливается.

При отпускании Aim визуальное направление сразу берётся из исходной физики,
а направление мыши перестаёт передаваться игровой логике. Запись углов
по-прежнему содержит `none` вне активного прицеливания. Оригинальный вывод
сохраняет собственную частоту обновления; ускорение визуального поворота
относится к Enhanced. Частота кадров/ввода и обновление анимации остаются.

## Реализация

mouse_aim.rs избирательно подменяет семь нативных чтений угла USA ROM.
Проверяются инструкция
ROM, адрес физики, указатель текущего игрока и его тип. Подмена применяется
к анимации, размещению частей, инициализации выстрела, направлению струи
огнемёта и смещению её точки выхода (включая 16-битное чтение целого угла). Физические чтения,
рассчитывающие движение WASD, получают исходный угол. ROM, DLL и сам угол
в гостевой памяти не переписываются. Перехват RtApi действует и при внутренних
выходах AOT через общий активный API. В interpreter-режиме функция недоступна.

Desktop преобразует мышь через SDL_RenderWindowToLogical, учитывая размер
окна, letterboxing и HiDPI. Для Enhanced сохраняется проекция корня игрока
из реально показанной интерполированной сцены, её масштаб и мировая позиция.
Обратная проекция курсора задаёт мировую цель; направление вычисляется
от актуальной физической позиции игрока. Это учитывает существующую задержку
представления камеры в 6 кадров. HUD не участвует в преобразовании.
Оригинальный вывод использует свои размеры и проекцию без широкого сдвига.

Object projection хранит проекцию корня и угол частей для прицела. Во время
активного режима поворот применяется обратной выборкой текстуры с расширением
границ спрайта, сохраняя порядок и прозрачность. При выключенном режиме
этот путь не применяется. Материалы, HUD и параметры камеры сохраняют
прежние алгоритмы. Wide остаётся 854×480 со сдвигом центральной области
на 67 пикселей. Прицел — нативный SDL-курсор 32×32 с прозрачным центром,
белыми пиксельными лучами и чёрной обводкой; после отпускания возвращается стрелка.

## Запись и повтор

При первом активном прицеливании Session создаёт рядом с input.gba-input
файл `aim.gba-aim`. В нём записаны изменения эффективного угла по кадрам:

```text
gba-aim v1
0 none
730 128
1050 768
1600 none
```

Углы 0..1023 соответствуют полному обороту: 0 — вверх, 256 — вправо,
512 — вниз, 768 — влево. `none` возвращает исходное поведение. До первого
включения файла нет. Обычные старые записи продолжают работать без него.

Runtime автоматически читает aim.gba-aim рядом с входным input.gba-input;
поэтому scripts/windows/replay.ps1 поддерживает такие записи без новых обязательных параметров.
Для отдельных опытов есть `--aim-input FILE.gba-aim`. Неправильный заголовок,
угол, порядок кадров или отсутствие начальной строки кадра 0 отклоняются.
Сам поток не включает пользовательскую настройку и не меняет controls.cfg.
