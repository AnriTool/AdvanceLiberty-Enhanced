# Переносимая сборка AdvanceLiberty: Enhanced

[English](../en/PORTABLE.md) | **Русский**

## Пользовательская папка

`AdvanceLiberty.exe` — единственная точка запуска. В поставке нет BAT/PS1,
компилятора, ROM, BIOS, сохранений, игровых записей или извлечённых языковых
пакетов. SDL и C runtime статически связаны; внешние Visual C++ Redistributable
и SDL2.dll не требуются. Платформа: Windows x64.

Пользователь распаковывает всю папку в доступное для записи место, помещает
собственный законно полученный USA `.gba` в `roms/` и запускает EXE.
Имя файла произвольное. Также поддержаны ROM в корне папки, перетаскивание
на EXE и `--rom FILE`. Для нескольких файлов выбирается первый подходящий
по точному SHA-256. Европейский или изменённый ROM не запускается.

```text
AdvanceLiberty.exe
README.txt
README.ru.txt
LICENSE
NOTICE
release.json
native/usa/manifest.json
native/usa/{precise,extra,mission,sessions}.dll
roms/PUT_YOUR_ROM_HERE.txt
languages/README.txt
licenses/
```

При старте EXE проверяет соответствие ROM поддерживаемому профилю и SHA-256
каждой DLL. Приложение не скачивает ROM или недостающие библиотеки.
При ошибке появляется окно с объяснением. Прямое выполнение нативного кода
для несовместимого ROM не начинается.

## Пути, настройки и диагностика

Пути вычисляются от EXE, а не от текущего каталога. `data/saves/usa.sav`
содержит игровой прогресс; резервная копия — `.bak`. `data/config/` хранит
пользовательские настройки. Не нужно переносить `controls.cfg` из рабочей
копии: при первом старте создаётся стандартный Enhanced-профиль.

По умолчанию включены Enhanced-рендер, Enhanced Audio, срок жизни дропа
30 секунд, 16:9, fullscreen и прицеливание при удержании ПКМ. Запись
диагностических сессий по умолчанию выключена; для сбора нативного покрытия
запускайте EXE с `--record-session`.
Явно сохранённые настройки не перезаписываются. `--original-audio` и `--drop-lifetime 0` позволяют отключить соответствующие изменения. `--help`
показывает параметры. Языковые пакеты находятся в `languages/`; английский
шаблон извлекается из ROM пользователя при первом запуске.

Лаунчер запускает тот же EXE в режиме игрового runtime без командной оболочки.
Вывод runtime попадает в `data/logs/launch-*.log`, диагностические записи при включении —
в `data/sessions/session-*`. Пользовательские [реплеи](REPLAYS.md) хранятся отдельно в `replays/`. Ошибка дочернего процесса показывается вместе
с концом журнала и его путём. Закрытие игры завершает и ожидающий лаунчер.
Низкоуровневый CLI для повторов и инструментов сохранён.

## Подготовка архива разработчиком

После изменения версии пакета в `Cargo.toml` выполните
`cargo update --offline --package advance-liberty`, затем
`python scripts/ci/release.py check-version`. Сохраните `Cargo.toml` и `Cargo.lock`
одним коммитом до создания тега релиза. CI проверяет совпадение версий;
сборки сохраняют `--locked`, чтобы не менять разрешённые зависимости автоматически.

`./scripts/windows/package.ps1 -Offline` собирает release EXE и создаёт новую папку и ZIP
`dist/AdvanceLiberty-Enhanced-VERSION-win64`. `-SkipBuild` использует готовый
EXE, `-OutputDirectory PATH` выбирает новый путь. Существующая папка никогда
не очищается и не перезаписывается, чтобы не затронуть добавленные ROM/сейвы.

Упаковка копирует только EXE, четыре проверенные DLL, сокращённый манифест,
инструкции и лицензии. Профили должны быть заранее собраны инструментами
CollectNative/UpdateNative/RebuildNative; эти инструменты остаются в проекте.
Сгенерированные C, покрытие, история исследований и пользовательские данные
в архив не включаются. Не упаковывайте папку после собственного тестирования
обычным архиватором: повторите `scripts/windows/package.ps1` с новым выходным каталогом.

`release.json` содержит версию и хеши файлов; рядом с ZIP создаётся `.sha256`.
Уведомления о сторонних компонентах сохраняют исходное авторство gba-recomp
и лицензии зависимостей. Названия сторонних проектов не меняются при ребрендинге.

[Сборка Linux и упаковка tar.gz](LINUX.md) используют отдельные бинарники платформы и shell-команды.
