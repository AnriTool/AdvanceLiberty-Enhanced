## Подтверждённые возможности

`src/options.rs` — отдельное host-меню: копия Controls/Preferences, отмена,
сохранение, захват клавиш, навигация мышью и геймпадом. `src/desktop.rs`
открывает его по Esc/Guide и останавливает исполнение через `paused()`.
`src/main.rs` в этой ветке не исполняет гостевые кадры. Звук очищается,
удержанные клавиши подавляются до отпускания. Эти механизмы следует сохранить.

Сейчас меню имеет собственную текстуру 720×480, фиксированные координаты,
встроенный шрифт 5×7 и несколько булевых переключателей страниц. Для нового
дерева страниц лучше явное состояние экрана/стек навигации. При поддержке
854×480 нужно согласованно менять текстуру, layout и преобразование мыши;
широкий мир сам по себе не расширяет меню.

## Шрифт и фон из USA ROM

Пользователь указал `../HTMLS/GTA_Advance_Studio_1.3/` и Europe ROM.
Изучены README, `js/tab_font.js`, `js/tab_menu.js`, графические модули Studio.
README Studio предупреждает о фиксированных адресах Europe. У поиска мелкого
шрифта опорный адрес 0x346828 относится именно к Europe; он не подходит как
опорный адрес USA. Однако структурный сканер графики меню пригоден и для USA:
на текущем ROM найдено 116 корректных записей.

Крупный жёлтый шрифт меню отличается от 8×8-шрифта вкладки Fonts Studio.
Он уже известен модулю `localization::install_color_font`:

| Данные | USA, файловое смещение | Europe, найденное точное совпадение |
| --- | --- | --- |
| Цветные знаки 16×16, 224×256 байт | 0x8314D0 | 0x831880 |
| Таблица ширин, 224 байта | 0x83F4D0 | 0x83F880 |
| Один из мелких шрифтов, 88×32 байт | 0x346478 | 0x346828 |

Каждая цветная буква состоит из четырёх 8×8-плиток с байтовыми индексами
оттенков. Индекс буквы — код символа минус 32; шаг — ширина плюс 2.
Палитра образца взята из 0x8312D0. При реализации нужно учитывать выбранный
языковой пакет и его color_font, а новые строки настроек включить в перевод:
существующий банк игровых строк не содержит названий всех Enhanced-функций.

Синий городской фон паузы извлечён декодером формата из tab_menu.js:

| Поле | USA, файловое смещение / значение |
| --- | --- |
| Запись изображения | 0xC98F60 |
| Палитра | 0x330940 |
| Плитки 4bpp | 0xC58C44 |
| Размер плиток | 0x40A0 байт |
| Tilemap | 0xC5CCE4 |
| Размер карты | 30×20 плиток, 240×160 пикселей |

Структура записи: palPtr, flags, tilesPtr, tilesSize, mapPtr, u16 width,
u16 height, u32 rest; размер 28 байт. Проверять границы и равенство
mapPtr = tilesPtr + tilesSize. Tilemap содержит индекс, отражения и банк
палитры. Фон получен из ROM без надписей; скриншот с затёртым текстом не нужен.

Локальные образцы: `artifacts/menu-research-20261025/rom-background-0.png`
и `custom-menu-style-proof.png`. Последний изображает новый список Options
на чистом фоне с оригинальным шрифтом. Это статический макет, не работающий UI.
Нельзя включать извлечённые ресурсы в исходники: runtime может читать их

## Рекомендуемая архитектура и порядок реализации

1. Сделать host-экран паузы с игровыми ресурсами. Его Settings использует
   нынешние Preferences/Controls и прежние правила Save/Discard. Сохранить
   Graphics, HUD, Language, Mouse Aim и все три профиля управления.
2. Ввести отдельный адаптер игровых действий: запрос из меню обрабатывается
   runtime на согласованной границе исполнения. Host-пауза полностью
   останавливает CPU, поэтому простая отправка нажатия в замороженную игру
   не выполнит команду.
3. Для Brief/Stats найти источники текущих данных и форматирование; для
   Camera, SFX/Music — штатные поля и процедуры применения. Проверить смену
   параметров и возврат в мир по оригинальному маршруту.
4. Перенаправить игровое Pause/Start в новый экран по действию профиля,
   включая переназначения и геймпад. `Context::Menu` сам по себе недостаточен:
   он объединяет паузу, стартовые экраны и неподдержанные состояния.
   Enter внутри меню остаётся подтверждением, а не повторным открытием.
5. Отдельно переносить старт, загрузку/создание/стирание слотов и игровые
   экраны сохранения. Для них требуется проверка игровых переходов и EEPROM,
   а не прямое изменение файла usa.sav или произвольный вызов Thumb-процедуры.

Для переходного прототипа допустима проверяемая последовательность штатных
GBA-команд до известного экрана с ожиданием состояния. Последовательности
фиксированных задержек без проверки состояния слишком хрупки для готового
меню. Долгосрочный вариант — собственное представление и проверенные игровые
команды. Их переходы должны записываться для детерминированного повтора:
нынешний input.gba-input хранит GBA-кнопки и события языка, но не новые команды.

Область первой версии — пауза и настройки. Наличие строки Multi Player в
банке не подтверждает работающий link-режим; обещать его перенос пока рано.
Продолжение игры, выход приложения и оригинальный Quit Game необходимо
различать. Save/Discard настроек также не равны сохранению игрового прогресса.

## Что проверить вручную

Из корня проекта запустить:

```powershell
.\tools\diagnostics\record-menu.ps1 -SkipBuild
```

Скрипт создаёт уникальный `artifacts/menu-play-...`, копирует туда сохранение,
controls.cfg и enhanced.cfg, запускает обычный runtime с записью сессии,
трассой текстов и контекста. Игровые записи и изменения настроек относятся
к копиям. Закрыть обычную игру перед исследовательским запуском; не менять
основные конфиги параллельно, чтобы итоговая проверка хешей была однозначной.

Сценарий: загрузить слот → Enter → последовательно открыть Brief, Stats,
Camera, Options. На каждом экране задержаться 2–3 секунды; в Stats проверить
прокрутку, в Camera — все значения и возврат. В Options проверить SFX в обе
стороны, Music, Controls, Credits и способы выхода. Затем штатный Quit Game
с отменой и подтверждением, стартовое меню и список слотов. Для первого
прохода достаточно не выбирать создание/удаление; после него определить,
нужно ли отдельно исследовать эти переходы на копии. Закрыть окно и сообщить
имя каталога, последовательность и любые неожиданные реакции.

Сессия позволяет позже воспроизвести нужные кадры и снять RAM/VRAM через
имеющийся `--capture-frames`; постоянные полные дампы памяти не нужны.

### Таблица действий и подтверждённые параметры

У исходного меню найдены структурированные описания. Основная пауза —
`0x0832C3D0`, Options — `0x0832F518`, Confirm Quit — `0x0832DB28`.
Заголовок содержит 6 слов, после него идут записи по 32 байта:
тип действия, ID строки, цена/служебное значение, условие/маска,
адрес вложенного меню, callback, аргумент. Типы 0/1/2 соответствуют
возврату / вложенному экрану / callback на исследованных пунктах.
Эта схема описывает также магазины и убежища; они не входят автоматически
в область замены меню паузы.

| Параметр | Обработчик Thumb (без бита 0) | Поле гостевой памяти | Значения |
| --- | --- | --- | --- |
| SFX | 0x08008008 | u8 0x02010C61 | 0 Off, 1 Low, 2 Medium, 3 High |
| Controls | 0x08008018 | u8 0x02010C7A | 0 Normal, 1 Alternate |
| Camera | 0x08008028 | u8 0x02010C66 | 0 Auto, 1 Low, 2 Medium, 3 High |
| Music | 0x08007C08 | u8 0x02001200 и звуковые процедуры | 0 On, 1 Off |

Значения подтверждены одновременно инструкциями обработчиков и изменениями
между снимками до/после выбора, а не только поиском похожих байтов.
Аргумент выбранного пункта находится в r2 в этих обработчиках.
Music On вызывает 0x080333DC, Off — 0x08034510; простая подмена одного
байта не воспроизводит звуковые побочные эффекты.
Original Normal/Alternate — настройка самой игры, отличная от режима
host-управления Enhanced/Classic и от трёх редактируемых профилей.

Stats запускается через 0x08006DC0. Оригинальный экран использует
0x08066B20 для ID названия показателя, 0x080669A4 для получения значения
и 0x08067054 для выбора денежного форматирования. Часть полей упакована
в битовые диапазоны: копировать произвольный массив u32 недостаточно.
Полная схема всех показателей ещё не восстановлена.
Brief запускается через 0x080073D8 и читает список указателей начиная
с 0x02010F70; перед рисованием возможна дополнительная обработка текста
через 0x0802DF34. В снимках этого прохода начальные записи списка пусты.

Для реализации теперь есть конкретные источники вместо слепой автоматизации
стрелок: описания экранов, обработчики и наблюдаемые значения. Безопасность
вызова этих процедур в произвольном CPU-состоянии этим не доказана;
production-адаптер должен работать через согласованные точки исполнения
и сохранять воспроизводимость записи.

## Реализация: собственный интерфейс поверх штатных действий

`src/game_menu.rs` читает фон, цветной атлас, ширины и строки из текущего
ROM в памяти. Наблюдатель инструкции 0x080011EC получает описание экрана
и выбранную строку перед оригинальной отрисовкой. Списки паузы, Options,
SFX, Music, Normal/Alternate, Camera и Confirm Quit заменяет host-отрисовка
720×480. Текст центрируется, выбранная строка выделяется, доступны мышь,
стрелки, Enter/J и D-pad/A/B геймпада.

Навигация host-интерфейса не пишет гостевую память и не вызывает произвольные
Thumb-функции. Курсор синхронизируется во время навигации обычными Up/Down,
с наблюдением подтверждённого индекса. Подтверждение A посылается только
после совпадения индексов. Пульс содержит 4 кадра удержания и 8 отпускания. Количество попыток
ограничено; без подтверждения индекса A не отправляется. Реальные GBA-кнопки
попадают в существующую запись ввода, дополнительных событий для повтора
не нужно. Штатная игра выполняет переключение звука, сохранение EEPROM,
переходы и подтверждения.

В паузу добавлены Enhanced Options и Exit Application. Enhanced Options
доступен также в Options; это прежний редактор копий Preferences/Controls
с обновлённым оформлением, прежними Save/Discard, языками и захватом привязок.
Его открытие полностью останавливает CPU/звук. Закрытие возвращает на тот
экран паузы/Options, откуда он был открыт. Игровой Quit Game и Exit Application
сохраняют разный смысл и отдельные подтверждения.

Esc из мира передаёт штатный Start, поэтому открывает ту же паузу, что и
действие Pause текущего профиля и Start геймпада. Guide также открывает паузу.
Esc внутри списков возвращает назад. На штатных страницах Enter/Esc означают
A/B независимо от Classic-привязок, Enter не передаёт одновременно Start.
Guide на этих страницах и Esc во время P-паузы открывают Enhanced Options. F5/F6/F8/F11/P остаются доступны
в новых списках. Потеря фокуса и удержанные кнопки сохраняют прежние защиты.

Brief, Stats и Credits пока используют штатную отрисовку страниц. Вход,
данные, автоматическая прокрутка и возврат сохранены; Enter/Esc возвращают
в собственный список. Стартовый экран, выбор/стирание слотов, магазины и
убежища также сохраняют прежнее представление. Новое меню не заявляет полной
замены всех интерфейсов ROM. Расширение собственного представления этих
страниц остаётся отдельной следующей частью работы.

Меню использует исходные пропорции 3:2. Рендер мира, широкая проекция,
HUD и Mouse Aim не менялись. При смене языкового пакета ресурсы меню заново
читаются из обновлённого ROM в памяти. Дополнительные названия host-настроек
пока сохраняют английский текст, как прежний Enhanced Options.

Обычный Play.cmd включает новый интерфейс. `play.ps1 -OriginalMenus`
передаёт `--original-menus` и возвращает прежнее сочетание Enter/оригинальной
паузы и Esc/Enhanced Options без записи предпочтения. Исследовательский
record-menu.ps1 явно использует этот режим. `--capture-frames` в оконном
повторе дополнительно сохраняет `NNNNNN-menu.ppm` для собственных списков.

Первый адаптер ошибочно предполагал циклическое движение вниз. Оригинал
останавливается на последней строке: выбор High → Auto и переход к Resume
из нижних строк могли дойти до лимита повторных Down, издавая много звуков.
Теперь при движении вверх используется Up; host-курсор также ограничен
границами списка. Навигация и подтверждение разделены, быстрый Enter может
дождаться уже запрошенного перехода. Esc отменяет ожидающую навигацию и
передаёт Back после отпускания предыдущего пульса.

Для выбора мышью и подтверждения ещё не синхронизированной строки скрытые
промежуточные перемещения исключены из звука SDL. Обычные перемещения и
финальное подтверждение остаются слышны. Исходные аудиобуферы игры и их
хеши не меняются. Вход в host-настройки очищает отложенные команды курсора.

Проверки: `artifacts/menu-fixes/tests.log` (runtime/AOT и пять SDL-проверок),
`native.log` (реальные ROM/AOT обработчики Auto → High → Auto, Resume,
повторная пауза, Confirm Quit/отмена, Esc/повторная пауза и выход к старту).
Новый `game_menu_native_tests.rs` выполняет переходы на initial.sav записи
25df0205 в памяти, без записи пользовательского сохранения. Запуск локально:
`cargo test --release --package gta-advance real_native_camera_roundtrip_resume_and_quit -- --ignored`.
SDL-тест отдельно проверяет Enter/Esc на fallback-страницах с обычными
Classic A/B на Z/X; старые привязки и профили не переписываются.
Итог: 129 runtime-тестов, тест AOT, пять SDL-проверок и отдельный native-прогон
прошли. Release EXE обновлён. Повтор записи 25df0205 совпал на всех 4344
видео/аудиокадрах, с прежними 109 интерпретациями. SHA-256 пользовательских
сохранения, конфигов, ROM и четырёх DLL до/после совпали; журналы и проверки
сохранены в `artifacts/menu-fixes/`.

### Названия и переводы собственного меню

Quit Game переименован в Quit to Menu, Exit Application — в Quit to Desktop.
Маршруты возврата к старту и сохранения перед закрытием остаются прежними.
Подписи паузы, настройки ПК и диалог выхода поддерживают необязательный
раздел `menu` языкового пакета v2. Каталог — `resources/menu-en.json`,
инструкция — `docs/LOCALIZATION.md`. Проверки локализации, смены алфавитов
и снимки реального SDL-рендера — `artifacts/menu-localization/`.

### Сохранение через Quit to Desktop

Диалог выхода из загруженной игры содержит Save game and exit, Exit without
saving и Back; по умолчанию выбран Back. Доступность определяется наличием
поддержанного игрового меню, поэтому до загрузки прогресса пункт сохранения
не предлагается. Из Enhanced Options это также можно выбрать через его
пункт выхода; отмена изменений Preferences/Controls при выходе сохраняется.

Save game and exit запускает конечный автомат в game_menu.rs: возврат к паузе,
Quit Game, выбор штатного Save and Quit. Все действия проходят через прежний
адаптер GBA-кнопок и записываются в сессию. Пока идёт сохранение, произвольные
нажатия и повторный запрос закрытия не прерывают запись. Потеря фокуса не
останавливает этот ограниченный маршрут меню. Скрытая навигация заменена
индикатором Saving game.

Успех фиксируется на USA 0x08007AD0: игра уже получила положительный результат
08000D80 и обращается за строкой Save Complete. 08007A2C сообщает Cannot Save
Now, 08007AEA — Save Error. Пока нет успеха, автомат не разрешает выход.
Во время этого маршрута обычная отложенная запись Save::update(false)
отключена: после успеха main вызывает Save::update(true), проверяет результат
атомарной записи и только затем разрешает Desktop::poll вернуть завершение.
При ошибке игры, диска или таймауте выход отменяется и показывается сообщение;
прежняя P-пауза восстанавливается.

Проверки находятся в artifacts/save-exit/. Native-тест выполняет реальное
Save and Quit из Options, проверяет, что до успеха файл не записан, после
записи совпадает с EEPROM, а .bak содержит исходный файл. Затем заново
запускает ROM, загружает слот и проверяет сохранённое изменение камеры.
SDL-тест проверяет диалог, запрет преждевременного закрытия, отказ диска и
завершение только после подтверждённого commit. Unit-тесты проверяют отказ
игры и недоступность сохранения до загрузки.
